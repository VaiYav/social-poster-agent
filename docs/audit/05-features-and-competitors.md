# 05 — Конкуренты и предложения по фичам

Глубокий внешний ресёрч (источники в конце; полные отчёты — в `docs/audit/_research/`). Фокус:
укрепление выбранного stealth-пути, пробелы в функционале, предложения по фичам.

---

## 1. Стратегический вывод (важнее любой отдельной фичи)

**Решение принято: путь — full stealth browser-automation, official API не используем.** Раздел исходит
из этого. Рыночный контекст ниже — только калибровка риска, не призыв «делайте как все».

Рынок почти весь на official API (Buffer, Publer, Typefully, Hypefury, Hootsuite, Sprout, SocialBee,
OSS Postiz/Mixpost/n8n). Из browser-automation-игроков заметен **Taplio** (LinkedIn), попавший под
зачистку в апреле 2025 — это напоминание, какой ban-риск принят сознательно и почему его обязательно
закрывать обвязкой из `03` (верификация публикации, изоляция fingerprint/IP, человекоподобные лимиты).

Экономика, к слову, играет **за** это решение по X: **X API с 6 февраля 2026 — pay-per-use** (~$0.015/
пост и **$0.20 за пост со ссылкой**, ×13 — ровно кейс промо-постера); бесплатного write-пути для нового
приложения практически нет. То есть на X «уйти на API» — ещё и дорого, а не только потеря контроля.

Бесплатные official API у Threads и FB-Pages существуют (фиксирую как факт), но **в работу не берём по
решению команды**. Что из этого важно держать в голове: для Threads и FB-Pages весь ban/SEC2-риск из
`03`/`04` остаётся на нас — значит эти сети требуют той же дисциплины обвязки, что и X.

**Стратегический приоритет — не «выбор транспорта», а закалка stealth-пути (раздел `03`).**

## 2. Ландшафт (как постят, AI, self-host, лицензия)

| Инструмент | Постинг | AI-генерация | Self-host | Лицензия/цена |
|-----------|---------|--------------|-----------|---------------|
| **Postiz** (OSS) | official API | да (ассистент) | да | AGPL; SaaS от ~$29/мес |
| **Mixpost** (OSS) | official API | базовая | да (Laravel) | self-host лицензия; Pro платно |
| **Typefully** | official API (X/Threads/LinkedIn) | да (хуки, репурпос) | нет | от ~$12–29/мес |
| **Hypefury** | official API | **нет нативной AI-генерации** | нет | ~$19–49/мес |
| **Buffer** | official API | да (AI Assistant) | нет | free tier + от ~$6/канал |
| **Publer** | official API | да; **reference-grade dedup** | нет | free + от ~$12/мес |
| **Taplio** | **browser-automation** (LinkedIn) | да | нет | ~$39+/мес; попал под бан-волну |
| **n8n / Make** | official API (ноды) | через LLM-ноды | да (n8n) | n8n Sustainable-Use; |

Вывод: SPA конкурирует не функциями, а способом доставки — и именно способ доставки несёт весь риск.

## 3. Пробелы в функционале (чего у SPA нет, а у зрелых инструментов есть)

| Пробел | Есть у | Заметка по SPA |
|--------|--------|----------------|
| Аналитика/инсайты постов | все | `metrics-scraper` — заглушка (`02 AN1`); реальной аналитики нет |
| Best-time-to-post | Buffer, Publer, Hypefury | нет; постинг по крону/задержке |
| Сокращение ссылок + UTM | большинство | нет; а ссылки ещё и удваивают цену X API |
| Медиа/изображения, alt-text | все | постинг только текстовый; quote-cards сломаны (`02 QC1`) |
| Контент-календарь (визуальный) | все | нет; есть очередь/история |
| Bulk-планирование (CSV) | Buffer, Publer, SocialBee | нет |
| RSS/evergreen-ресайклинг | SocialBee, Publer | recycling есть, но сломан/не запускается (`02 RC1-3`) |
| Мульти-аккаунт, роли/RBAC, многоступенчатый аппрув | Hootsuite, Sprout | один аккаунт/сеть; нет ролей; аппрув одноступенчатый |
| Адаптация контента per-network | частично у всех (ручная) | **у SPA сильнее** — генерит разный контент per-network |
| Brand-voice, обучающийся на прошлых постах | Typefully и др. | brand-voice статичный файл; hook-bank не учится (`02 AN1`) |
| Fact-checking сгенерированного | **ни у кого** | открытая ниша для бренда, делающего фактические заявления |

## 4. Предложения по фичам (приоритизировано)

### Tier 0 — снимают риск/чинят мёртвое (делать первым)
1. **Закалка stealth-обвязки (`03`) — главный риск-контроль, раз API не используем:** изоляция
   fingerprint/IP per-account, человекоподобные лимиты (чинит `02 R1`), re-login вне постинга. Без
   этого stealth-путь несёт полный ban-риск.
2. **Починить/удалить мёртвые фичи** перед добавлением новых: recycling (`02 RC1-3`), quote-cards
   (`QC1`), engagement rate-limit (`R1`), metrics-scraper (`AN1`). Сейчас они создают ложное ощущение
   функционала.
3. **Верификация факта публикации + идемпотентный ключ + reaper stuck-POSTING** (`03 §1-2`) — без
   этого любой рост объёма даёт дубли/потери.

### Tier 1 — близко к данным, которые уже есть
4. **Реальная аналитика постов** — где метрики доступны **бесплатно** по официальному read-API
   (Threads insights, FB Page insights), берём оттуда; X (read платный) — пока не делаем. Чинит
   заглушку `02 AN1`, питает best-time-to-post и hook-bank (который тогда наконец «учится»).
   Примечание: это **read**-API для метрик, постинг остаётся stealth.
5. **UTM + сокращение ссылок** — дёшево, измеримо; ссылку часто полезно выносить в reply, а не в
   корень (и для охвата, и как более человекоподобный паттерн).
6. **Backend-валидация на аппруве** (char-limit/bait/forbidden) — закрывает `02 PO2` и делает ручной
   аппрув таким же безопасным, как авто.
7. **Единый decision-gate с «preview/dry» режимом**: N дней логировать, что авто-аппрув *сделал бы*,
   не публикуя — безопасный разгон автономности (`01 A1`).

### Tier 2 — продуктовые отличия
8. **Fact-check сгенерированного контента** (особенно для астрологического/«фактического» бренда) —
   ниша, которую не закрывает никто; снижает репутационный риск авто-постинга.
9. **Медиа/изображения в постах** + рабочие quote-cards (с реальным шрифтом) — текст-онли сильно
   ограничивает охват.
10. **Визуальный контент-календарь** поверх существующей очереди/истории.
11. **Multi-account + роли/многоступенчатый аппрув** — если инструмент выйдет за рамки одного бренда.

### Не регрессировать при рефакторинге
Per-network генерация *разного* контента и HITL «generate → review → post» — это то, к чему рынок
пришёл; при вынесении портов/починке багов **не потерять** эти два свойства.
